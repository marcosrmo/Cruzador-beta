🛠️ Relatório de Melhoria e Plano de Ação Detalhado: Autenticação
A falha na autenticação após o deploy é causada pela desconexão de dados entre o ambiente de build/seed e a lógica de login. O servidor Express está rodando, as tabelas existem (graças ao db:push), mas o usuário criado pelo seed.ts não consegue ser validado pelo processo de login.
1. ⚙️ Criação do Hash da Senha (O Seed - script/seed.ts)
O primeiro ponto de falha é a criação do usuário. A senha precisa ser hasheada corretamente.
| Aresta | Melhoria Proposta | Ação Necessária |
|---|---|---|
| Caminho do Schema | Conferir Importação: Garanta que o caminho para o schema (users) e o objeto db estejam 100% corretos. | Revisão: Confirme se o import { db } e o import { users } estão apontando para os locais certos (server/db/index.ts e server/db/schema.ts ou similar). |
| Geração do Hash | Usar bcryptjs Assíncrono: O bcrypt.hash deve ser chamado corretamente com um salt forte. | Revisão: Garanta que o seed.ts está usando await bcrypt.genSalt(10) e await bcrypt.hash(senha_bruta, salt). |
| Inserção Mínima | Nome das Colunas: Garanta que o objeto inserido ({ email, password: hash }) usa os nomes exatos das colunas definidas no seu schema.ts. | Revisão: Verifique se as colunas são email e password (e não username ou hashedPassword). |
2. 🔑 Lógica de Login (A Comparação - server/auth/index.ts ou similar)
O segundo ponto de falha é a comparação da senha. O servidor precisa pegar a senha digitada pelo usuário e compará-la com o hash armazenado no banco de dados.
| Aresta | Melhoria Proposta | Ação Necessária |
|---|---|---|
| Comparação de Hash | Uso de bcrypt.compare: Esta função é a única forma segura de comparar a senha bruta do login com o hash armazenado. | Revisão: O arquivo de autenticação deve ter: const isValid = await bcrypt.compare(senha_bruta_do_login, hash_do_banco); |
| Campos de Login | Sincronia de Campos: O backend deve esperar receber email (ou username) e password, exatamente como o frontend envia (JSON.stringify({ username, password })). | Revisão: Se o frontend envia username, o backend deve buscar por username. Se o DB só tem email, o frontend deve enviar email. Seu frontend usa username (veja login(username, password)), mas seu DB provavelmente usa email. Corrija a inconsistência. |
| Tipo de Password | String Pura: Garanta que a coluna password no seu schema.ts esteja definida como text ou varchar para armazenar o hash longo gerado pelo bcrypt. | Revisão: Confirme a definição da coluna password no schema. |
3. 🛡️ Segurança e Variáveis de Ambiente (Render)
A persistência de credenciais no ambiente de produção.
| Aresta | Melhoria Proposta | Ação Necessária |
|---|---|---|
| Variáveis Ocultas | Usar o Render Secreto: Suas credenciais ADMIN_EMAIL e ADMIN_PASSWORD devem ser definidas no painel de "Meio ambiente" (Variáveis Ambientais) do Render. | Concluído? Verifique se você adicionou ADMIN_EMAIL e ADMIN_PASSWORD no painel do Render. |
