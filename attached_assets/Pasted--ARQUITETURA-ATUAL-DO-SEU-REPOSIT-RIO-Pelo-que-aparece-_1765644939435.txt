📁 ARQUITETURA ATUAL DO SEU REPOSITÓRIO

Pelo que aparece no GitHub, seu projeto tem:

/
├─ attached_assets
├─ client/
├─ script/
├─ server/
├─ shared/
├─ .gitignore
├─ GUIA_DEPLOY.md
├─ package.json
├─ tsconfig.json
├─ vite.config.ts


🟡 Isso indica que você tem um projeto fullstack monorepo com:

client/ frontend

server/ backend

shared/ código reutilizado

Arquivos de configuração package.json, tsconfig.json, etc. 
GitHub

Isso é ótimo — agora precisamos fazer com que o Render entenda apenas o backend quando for implantar o serviço web.

🚀 PASSO A PASSO COMPLETO PARA DEPLOY NO RENDER
✅ 1️⃣ CONFIRME O BACKEND

O Render precisa rodar apenas o backend.
No seu caso, isso é o conteúdo da pasta:

/server


👉 Esse diretório deve conter o seu servidor Node/Express (ou TS) que escuta process.env.PORT.

Se ainda não estiver lá, mova ou estruture assim:

server/
├─ index.ts (ou index.js)
├─ package.json
├─ src/ (opcional)
├─ routes/
├─ controllers/
├─ middlewares/

✅ 2️⃣ PACKAGE.JSON DO BACKEND

Precisamos de um package.json apenas no servidor (server/).
Ele deve definir o script de produção como:

"scripts": {
  "start": "node index.js"
}


⚠️ Não use:

"dev": "nodemon"


Isso é fundamental para o Render saber como iniciar o app corretamente. 
Render

✅ 3️⃣ PORTA DINÂMICA

No arquivo server/index.js ou server/index.ts, deve existir:

const PORT = process.env.PORT || 3000;
app.listen(PORT, () => console.log(`Servidor rodando na porta ${PORT}`));


Isso é obrigatório no Render, porque a plataforma define a porta em process.env.PORT. 
Medium

✅ 4️⃣ REMOVA SESSÃO EM MEMÓRIA (SE HOUVER)

Se você estiver usando sessão com memória, troque por JWT ou outra solução que não dependa de armazenamento local. Render reinicia o app e isso quebra sessões em memória.

✅ 5️⃣ VARIÁVEIS DE AMBIENTE NO RENDER

Depois que o serviço estiver criado no Render (Web Service), entre em:

Environment → Environment Variables


Adicione:

NODE_ENV = production
DATABASE_URL = (URL do PostgreSQL)
JWT_SECRET = (sua chave secreta)


⚠️ Jamais suba .env para o GitHub — coloque as variáveis no painel do Render mesmo. 
CrazyStack

✅ 6️⃣ CONFIGURAÇÃO DO RENDER

Ao criar Web Service no Render, configure:

Campo	Valor
Name	Cruzador-de-Planilhas
Language	Node
Branch	main
Root Directory	server
Build Command	npm install
Start Command	npm run start ou node index.js

🔹 Se o backend for em TypeScript e precisa de build, adapte para:

Build Command

npm install && npm run build


Start Command

node dist/index.js


Depende de como está o package.json do backend.

📌 Render vai rodar dentro de server/ porque você colocou isso em Root Directory. 
Render

✅ 7️⃣ FRONTEND CONFIGURATION

O client/ não deve ser parte do Web Service diretamente.

Se você quer servi-lo pelo backend, tenha uma rota no Express que sirva os arquivos estáticos do build:

app.use(express.static(path.join(__dirname, "../client/dist")));


E no React:

npm run build


Isso faz o backend enviar o build pronto para a web.

📦 POSSÍVEL PACKAGE.JSON MONOREPO

Ele pode ter scripts como:

"scripts": {
  "start": "node server/index.js",
  "client": "cd client && npm start",
  "server": "cd server && npm start"
}


Mas no Render só importa o que está em server/.

🧪 DEPLOY AUTOMÁTICO

Depois da 1ª implantação:

Toda vez que você der git push main

O Render rebuild automaticamente

Publica sua atualização

🧠 DIAGNÓSTICO DE ERROS

Se der erro no Render, veja Render Dashboard → Logs.

Erros mais comuns:

❌ Port não definida
Error: listen EADDRINUSE


👉 Ajustar o código para usar process.env.PORT. 
Medium

❌ Build falhou
npm ERR! Missing script: start


👉 Colocar "start" no package.json.

❌ Não encontra diretório
No such file or directory


👉 Root Directory está errado.

🟢 RESUMO DE VERIFICAÇÃO

Antes de tentar deploy:

✅ server/package.json tem "start"
✅ server/index.js usa process.env.PORT
✅ .env não está no GitHub
✅ Variáveis colocadas no Render
✅ Root Directory no Render = server
✅ Build e Start configurados corretamente
